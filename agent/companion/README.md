# SmartFlow Coding Companion (ENG-03 v0)

A small local Node.js service that runs Claude Code non-interactively against
an explicitly allow-listed repository, on a freshly created isolated branch,
and independently verifies what actually happened from git/GitHub ground
truth rather than trusting Claude's own self-report.

**Not part of the SmartFlow production Worker or frontend.** This is a
standalone local-dev process (`agent/worker/` and `src/` are untouched).
Claude Code is the only backend (no provider abstraction yet — see
[ENG-02](../../docs/architecture/notes/eng-02-pluggable-coding-agents-spike-v1.md)
for why that's deliberately deferred).

## Safety model

- **Repository allowlist**: only repos in `COMPANION_ALLOWED_REPOS` are ever touched.
- **One isolated branch per task, always freshly created off `main`**: the
  branch name is generated by the companion; there is no request field that
  accepts a caller-supplied branch or merge target. A request that tries to
  name `main`/`master` at all is rejected outright (`MAIN_TARGET_DENIED`).
- **Claude Code never runs git.** `--disallowedTools "Bash(git*)"` is passed
  on every invocation — a deny rule, evaluated before permission mode, so
  this is not merely a prompt instruction. The companion's own code (`git.js`)
  performs every commit and push, and independently refuses to act on
  `main`/`master` before every checkout/commit/push call, structurally, not
  just at the API boundary.
- **No merge, ever.** Landing a branch into `main` is a manual PR, exactly
  like every other change in this repo.
- **Self-report vs. verified result.** Claude's own JSON output is treated as
  advisory only. The companion always independently re-derives branch name,
  HEAD SHA, changed files, commits, remote push state, and `main`'s SHA
  before/after from git and the GitHub API, and flags any disagreement
  between what Claude claimed and what's actually true.
- **Minimal environment.** Both the git and Claude Code subprocesses get an
  explicit allowlisted environment (PATH/HOME/etc.), never a spread of the
  parent process's env — no ambient API key can reach either subprocess by
  accident. Claude Code needs no credential at all here (it authenticates via
  its own local login); git push relies on the ambient credential helper
  already configured on the host, never a token in a prompt or log.
- **Redaction backstop.** Anything captured from Claude's stdout/stderr is
  passed through a secret-shaped-string scrubber before being logged or
  returned, as defense in depth on top of the point above.

## Configuration (env vars)

| Var | Required | Default | Purpose |
|---|---|---|---|
| `COMPANION_ALLOWED_REPOS` | yes | — | Comma-separated `owner/name` allowlist |
| `COMPANION_SHARED_TOKEN` | yes | — | Required `X-Companion-Token` header value |
| `COMPANION_PORT` | no | `8971` | HTTP port |
| `COMPANION_WORKSPACE_ROOT` | no | OS temp dir | Where per-repo clones live |
| `COMPANION_CLAUDE_BIN` | no | `claude` | Claude Code binary to invoke |
| `COMPANION_GIT_REMOTE_BASE` | no | `https://github.com` | Overridable for local test fixtures |
| `COMPANION_DEFAULT_TIMEOUT_SECONDS` | no | `300` | Per-task timeout |
| `COMPANION_MAX_BUDGET_USD` | no | `2` | Passed to Claude Code's own `--max-budget-usd` |

## Running

```
cd agent/companion
COMPANION_ALLOWED_REPOS="owner/name" COMPANION_SHARED_TOKEN="<pick-one>" node src/index.js
```

Submit a task (stands in for "SmartFlow submits a coding task" — not a
change to the real SmartFlow frontend/Worker):

```
COMPANION_SHARED_TOKEN="<same-token>" node scripts/submit-task.js \
  --repo owner/name --taskId my-task-1 --instruction "..." [--timeoutSeconds 180]
```

## Testing

```
npm test -- agent/companion   # from the repository root
```

Tests use a throwaway local bare git repo as a fake "origin" and a set of
fake `claude` fixtures (success, no-op, failure, timeout, secret-leak) —
no real network calls, no real Claude Code invocation, no cost.
